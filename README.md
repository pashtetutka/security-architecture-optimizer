# Security Architecture Optimizer (SAO)

Прототип информационно-аналитической системы оптимизации архитектуры средств защиты информации вычислительной инфраструктуры.

**Статус:** MVP 0.1 — объяснимое многокритериальное ранжирование SIEM с обязательными ограничениями.

## Задача

Система получает профиль инфраструктуры, каталог решений и критерии выбора,
отфильтровывает решения, не удовлетворяющие обязательным требованиям,
вычисляет прозрачный рейтинг допустимых вариантов и выдаёт причины отказов
и подробный вклад критериев в итоговую оценку.

SIEM — первый реализуемый класс СЗИ. В перспективе модель расширяется
на EDR, NGFW, DLP и анализ их совместимости и совокупного покрытия угроз.

## Запуск

Требуется Python 3.10+; внешних зависимостей нет.

Для запуска из корня проекта:
```bash
PYTHONPATH=src python -m sao.cli --profile data/examples/infrastructure.json --catalog data/examples/products.json
```

В Windows PowerShell:
```powershell
$env:PYTHONPATH="src"; python -m sao.cli --profile data/examples/infrastructure.json --catalog data/examples/products.json
```

Тесты:
```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

## Методика MVP

1. **Hard constraints**: обязательные требования проверяются до расчёта рейтинга.
2. **Нормализация**: значения критериев хранятся в шкале 0–100. Чем выше, тем лучше.
3. **Весовая оценка**: `S = sum(w_i * score_i) / sum(w_i)` (веса > 0).
4. **Объяснимость**: для каждого решения сохраняются причины исключения
   и покритериальный вклад в балл.
5. **Пропуски**: при отсутствии оценки критерия решение исключается из ранжирования
   до проверки данных, а не получает придуманный ноль.

Профиль, веса и исходные оценки в примере **синтетические**. Нельзя интерпретировать
результат как реальное сравнение вендоров.

## Ограничения и планы

- Это прототип ранжирования продуктов, **не** готовый оптимизатор архитектуры.
- Пока нет автоматического импорта оригинальной таблицы, расчёта CAPEX/OPEX,
  проверки интеграций и формальной модели покрытия угроз.
- ML/LLM пока не реализованы. Планируем использовать LLM для извлечения
  утверждений из документации с обязательными ссылками на источники и ручной верификацией.
- Следующий этап — модель «активы → угрозы → меры → СЗИ → ограничения → целевая архитектура».

См. [дорожную карту](docs/ROADMAP.md), [описание схемы данных](docs/DATA_MODEL.md).

## Данные и публикация

Исходная рабочая таблица `SIEManal` **не включена**: потенциально содержит
коммерческие предложения и непроверенные/устаревающие характеристики.
В публичный репозиторий добавляются только открытые или синтетические данные.
Сведения о вендорах требуют указания источника, даты и степени подтверждения.
