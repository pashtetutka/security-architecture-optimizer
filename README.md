Проект формирует воспроизводимую основу для исследования и сопоставления SIEM:
преобразует официальные HTML-, PDF- и JSON-документы в структурированные сведения
об источниках событий и требованиях к инфраструктуре. Каждое утверждение связано
с документом, URL, датой получения, SHA-256 и фрагментом первоисточника.

| Характеристика | Описание |
| --- | --- |
| Решаемая задача | Снижение трудоёмкости сбора и приведения разнородной документации SIEM к единому формату |
| Область данных | Поддерживаемые источники событий и системные требования |
| Вход | Официальные документы вендоров и сохранённые снимки |
| Результат | Типизированные JSON-каталоги, перечень уникальных значений и HTML-отчёт |
| Масштаб исследования | Реестр 13 SIEM; покрытие определяется доступностью и содержанием документации |
| Текущий этап | ETL и контроль качества данных; подготовка к последующей обработке |

## Решаемая проблема

Сведения об интеграциях, версиях источников, EPS, серверных ролях и аппаратных
ресурсах публикуются в разных форматах и для разных сценариев установки.
Прямое объединение этих сведений приводит к несопоставимым результатам: варианты
названий считаются разными продуктами, минимальные конфигурации смешиваются с
рекомендованными, а отсутствие опубликованного параметра трактуется как отсутствие
поддержки. ETL сохраняет условия применимости и происхождение фактов, обеспечивая
проверяемость последующей исследовательской обработки.

## Возможности

- Получение документов по HTTPS с проверкой TLS и `robots.txt`.
- Сохранение исходных снимков и проверка SHA-256 при повторном извлечении.
- Специализированные адаптеры таблиц, PDF и публичных API вендоров.
- Единые идентификаторы источников, явные алиасы и раздельное хранение версий.
- Сохранение сценариев EPS, ролей узлов, альтернатив CPU и ОС, дисковых групп и ограничений.
- Проверка контракта JSON, отчёты полноты и диагностика неподдерживаемой разметки.
- Повторная нормализация без сети и объединение независимых выгрузок.

## Установка

Требуются Git и Python 3.10 или новее. Команды выполняются из корня репозитория.

```bash
git clone https://github.com/pashtetutka/security-architecture-optimizer.git
cd security-architecture-optimizer
python -m venv .venv
```

Активация окружения в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

В Linux и macOS:

```bash
source .venv/bin/activate
python -m pip install -e .
```

## Использование

Проверка контрольного набора и создание HTML-отчёта без сетевых обращений:

```bash
python -m siem.etl check --etl data/etl/repro/vendors.json --automatic-only
```

Отчёт доступен по пути `results/etl_audit/report.html`. Каждый запуск сохраняется
в новом каталоге `results/history/check_*`; предыдущие результаты остаются доступными.

Для получения новых документов сначала просмотрите зарегистрированные адреса:

```bash
python -m siem.etl crawl --dry-run --only p12
```

Параметры сетевого сбора, дополнительных CA, объединения выгрузок и целевой
нормализации приведены в [руководстве ETL](docs/etl.md).

## Контрольный набор данных

В репозитории находятся манифест и **37 исходных снимков**. Режим
`--automatic-only` использует документы с зафиксированным способом получения
`automatic_https`.

| Показатель | Контрольный набор в Git | Локальный набор с обзором Ankey 5.2.8 |
| --- | ---: | ---: |
| SIEM в реестре | 13 | 13 |
| Записи об источниках событий | 1451 | 1481 |
| Профили ресурсов | 25 | 25 |
| Типизированные требования | 67 | 67 |

Контрольный набор содержит **1165 уникальных идентификаторов источников**.
Несколько записей одной сущности могут описывать разные версии, нормализаторы
или способы сбора. Исторические 179 записей частичной поддержки MaxPatrol
сохраняются для аудита и исключаются флагом `--automatic-only`.

Дополнительные 30 записей Ankey извлекаются из двух таблиц официального обзора
5.2.8: 23 новых и 7 обновлённых источников. В документе указано ограничение
перепубликации, поэтому PDF не включён в Git. Порядок его загрузки и подключения
описан в [документации](docs/etl.md#дополнительный-каталог-ankey).

## Проверка качества

```bash
python -m unittest discover -s tests -v
```

Команда `check` также запускает эти тесты; для повторного просмотра данных без
тестового прогона предусмотрен `--no-tests`. CI выполняет проверки в Windows,
Linux и macOS. Реальные результаты запусков доступны по значку проверки в начале README.

Основной PDF-парсер использует `pypdf`. Проверка необязательного инструмента
`pdf-candidates` пропускается без PyMuPDF. Интеграционный тест Ankey требует
локального PDF; в свежем клоне его отсутствие явно отражается как `skipped`.
Регрессионные тесты входят в репозиторий, но не в устанавливаемый пакет.

## Границы применимости

ETL поддерживает воспроизводимую обработку контрольного набора. Автоматическое
извлечение не присваивает статус `verified` и не разрешает расчёт ресурсов без
проверки смысла, версии и условий применимости данных. Закрытая документация,
запреты доступа, противоречия первоисточников и ненормализованные разделы отражаются
в отчёте. Их актуальное состояние приведено в [аудите по SIEM](docs/vendor_audit.md).
