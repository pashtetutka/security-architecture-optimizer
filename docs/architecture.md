# Структура ETL

```text
src/siem/etl/
  cli.py, __main__.py    единый CLI
  commands/             обработчики сбора, нормализации и ручной проверки
  fetcher.py            HTTPS, robots.txt, повторы, ограничения загрузки
  pipeline.py           сбор документов, исходных снимков и происхождения фактов
  extractors.py         первичное извлечение таблиц, ссылок и кандидатов
  catalog.py            сборка нормализованного каталога и запись JSON
  sources.py            нормализация опубликованных источников событий
  requirements.py       общие строгие правила ресурсов и зависимостей
  storage.py            ёмкости дисков, количество устройств и единицы сети
  common.py             текст, null-значения, константы и доказательные фрагменты
  vendors/              komrad.py, alertix.py, rvision.py, rusiem.py
  reports/              quality.py, readiness.py
  coverage.py           сопоставление перечня источников организации
  applicability.py      существующий экспериментальный расчёт применимости
  pdf_docs.py           кандидаты из PDF для ручной проверки
```

`fetcher → pipeline/extractors → catalog → reports`: получение документа отделено
от нормализации, а нормализация — от проверки структуры и готовности.
Адаптеры в `vendors/` используют общие утилиты и не импортируют CLI или каталог.
`catalog.py` выбирает адаптер по продукту и назначению документа, проверяет снимки,
объединяет данные и формирует диагностику. Команды вызывают эти функции.

Тесты `test_collection`, `test_catalog`, `test_system_requirements`, `test_komrad`,
`test_source_review`, `test_extraction_regressions`, `test_evidence_scope`, `test_cli`
описывают поведение. Название релиза не задаёт место теста или реализации.

При добавлении правила сохранять первоисточник, область применимости, неизвестные
значения и исходные единицы. Добавлять сценарий в соответствующий тестовый модуль,
по возможности с настоящей разметкой документа. При структурных изменениях сравнивать
все выходные JSON с контрольной нормализацией в отдельном каталоге.
