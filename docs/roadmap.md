# План развития

## ETL: готов к исследовательской обработке сохранённых данных

- Реестр 13 SIEM и специализированные адаптеры опубликованных документов.
- HTTPS, проверка TLS и robots.txt, сохранение оригиналов и SHA-256.
- Нормализация источников событий и системных требований с происхождением фактов.
- Устойчивые идентификаторы и явные алиасы, сохранение версий и областей поддержки.
- Проверка структуры, отчёты качества, диагностика отсутствующих и спорных данных.
- Воспроизводимая проверка без сети; отдельный режим без ручного импорта.
- Регрессионные тесты на сохранённых HTML/PDF/JSON; CI для Windows, Linux, macOS.

Критерий приёмки: команда из README проходит на сохранённом наборе и выдаёт
1451 запись источников, 25 профилей и 67 требований без структурных ошибок.
Полное покрытие всех продуктов и текущая доступность сайтов в этот критерий не входят.
Фактический результат CI на других ОС проверяется после публикации изменений.

## Следующий этап: обработка и проверка данных

1. Зафиксировать версии и область применимости выбранных наборов данных.
2. Организовать ручную сверку извлечённых фактов с evidence и регистрацию решений.
3. Разрешить противоречие среднего профиля Ankey либо исключить его из расчётов.
4. Определить правила сопоставления входных источников организации с каталогом.
5. Допускать к расчёту ресурсов только проверенные профили с достаточными условиями.

## Дальнейшее расширение ETL

Добавлены матрица KUMA по EPS, минимальная конфигурация Kubernetes и базовые
требования агентов с альтернативами ОС и условиями glibc. Отдельные разделы
Метрик, производительности коннекторов и дополнительных сервисов ещё требуют
нормализации и явно отмечены в отчёте. Для Ankey добавлен локальный разбор
30 записей из таблиц 3.1/3.2 обзора 5.2.8; PDF не входит в Git из-за ограничения перепубликации.

Добавлять документы и адаптеры по исследовательской необходимости. Для каждого
нового парсера сохранять оригинал и регрессионный пример. Закрытая документация,
запрет robots.txt и неопубликованные параметры остаются явными ограничениями.
Повтор сетевого сбора проверяет доступность на дату запуска и не обещает полноту.
