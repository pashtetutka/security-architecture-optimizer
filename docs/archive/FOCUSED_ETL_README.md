# SIEM ETL v0.7 — только источники событий и системные требования

## Цель

Единая **структура данных**, не единый текстовый список. Сбор источников производится существующим безопасным `all_cli crawl` (официальные ссылки, robots.txt, HTTPS, снимки документов); новый модуль отвечает за строгую нормализацию из собранных документов.

Из ETL на данном этапе **исключены**: ФСТЭК, сертификация, лицензирование, стоимость, продуктовые оценки, рейтинг, произвольные фрагменты текста. `assess` из предыдущих версий **не используется**.

## Что делается автоматически

- RuSIEM, R-Vision, KUMA: известные структурированные каталоги интеграций. Категории (`source_family`) и текстовые кандидаты (`review_candidate`) пропускаются. Дубли объединяются, источники доказательств сохраняются.
- R-Vision: извлечение записей из таблиц конфигураций **EPS — состав серверов** (`vcpu`, `ram_gb`, `disk_gb`, `disk_type`, `quantity`, `role`, минимальная/рекомендуемая схема); отдельные явные требования к Kubernetes и СУБД.
- Alertix: минимальные и рекомендуемые CPU/RAM схемы *all-in-one* из официальной sizing-таблицы. Диски не рассчитаны автоматически, чтобы не потерять смысл нескольких накопителей и RAID.
- KOMRAD: редакции Base-SMART/BASE/All-in-One/Enterprise, физические ядра, RAM, диск; отдельный индекс руководств по источникам событий.
- Для остальных SIEM выходные разделы пока остаются пустыми (`no_normalized_data=true`), пока нет специализированных адаптеров или доступной для них структурированной документации. Это **не** свидетельство отсутствия возможности у продукта.

Десять новых тестов проверяют узкие правила извлечения. Это тесты на локальной разметке, **не подтверждение качества всех реальных сайтов**. Название версии в URL сохраняется как `siem_version_hint`, не как подтверждённая версия продукта.

## Установка патча

1. Сделайте коммит или резервную копию текущего проекта v0.6.
2. Скопируйте ZIP в корень репозитория и в PowerShell выполните:

```powershell
Expand-Archive .\siem-etl-v07-focus-patch.zip -DestinationPath . -Force
python -m pip install -e .
python -m unittest discover -s tests -v
```

3. Добавьте три **уже проверенных по официальным порталам** адреса в манифест (Alertix hardware, KOMRAD source index и KOMRAD hardware):

```powershell
python -m siem.etl.focused_cli enrich-registry --registry data/etl/vendors.json --extra docs/FOCUSED_OFFICIAL_URLS.json
```

Команда идемпотентна: повторный запуск не создаст дубликатов.

4. Соберите все 13 продуктов без VPN (либо выборочно `--only p03 p04 p13`). Сохраняйте исходные документы:

```powershell
python -m siem.etl.all_cli crawl --timeout 30 --retries 1 --snapshot-dir results/raw --output results/vendors_focus_raw.json
```

5. Преобразуйте в **только две группы**:

```powershell
python -m siem.etl.focused_cli normalize --etl results/vendors_focus_raw.json --output-dir results/focused
```

## Выходные файлы

| Файл | Содержание |
|---|---|
| `sources.json` | SIEM, версия/подсказка, источник, версия источника, способ получения, нормализатор, URL, хеш документа, дата, статус проверки |
| `sizing_profiles.json` | EPS-диапазон, сценарий, роли узлов и их вычислительные ресурсы. Физические CPU cores **не приравниваются** к vCPU |
| `system_requirements.json` | Дискретные требования: компонент, свойство, значение, единица, обязательность, применимость, происхождение |
| `coverage.json` | Какие данные удалось **структурированно** нормализовать для каждой из 13 SIEM |
| `unread_system_documents.json` | Какие сохранённые HTML-снимки нельзя было открыть или их SHA-256 не совпал |

Размер некоторых полей оставлен `null`. Это требование достоверности, а не ошибка. Если факт получен из PDF или произвольного текста, он **не попадёт** в системные требования без отдельного детерминированного правила.

## Проверка

1. Откройте `results/focused/coverage.json`: там по каждой SIEM отдельно количество интеграций, профилей и системных требований. Ноль = «не нормализовано», а не «не поддерживается».
2. Откройте `results/focused/sources.json`: проверьте названия и версии источников, URL и наличие нормализаторов. У KUMA должны быть поля `normalizer_id`, у R-Vision — `collection_method`, если соответствующая ячейка заполнена у вендора.
3. Откройте `results/focused/sizing_profiles.json`: для каждого профиля должны быть *сценарий* и *роль сервера*. Нельзя складывать рекомендованные и минимальные конфигурации или приравнивать физические ядра к vCPU.
4. Сверьте 5–10 строк из каждого каталога и все извлечённые профили ресурсов с сохранёнными HTML из `results/raw`. Данные пока `extracted_unverified`.

## Известные ограничения

- Версии самих SIEM не подтверждаются автоматически. `latest` / `next` — **не версии**.
- Прямое скачивание MaxPatrol блокировалось TLS-ошибкой на компьютере пользователя. Отключать TLS-проверку не нужно; доступно ручное сохранение официального руководства через предусмотренный в старом ETL `--manual-dir`.
- KUMA 4.0/4.2 публикует большие таблицы sizing (включая PDF); **их адаптер в v0.7 ещё не создан**. В этой версии не делаем вид, что PDF произвольного формата нормализован.
- Для Alertix несколько накопителей SSD/SAS и RAID ещё требуют отдельной модели хранения. CPU и RAM извлекаются без фиктивного суммирования дисков.
- KOMRAD и R-Vision имеют разные формы sizing и условия применимости; отдельные адаптеры — намеренное решение.
- Индекс документации KOMRAD проверяет наличие инструкций по подключению, не доказывает наличие готового нормализатора.
