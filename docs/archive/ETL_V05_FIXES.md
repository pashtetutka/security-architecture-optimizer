# ETL v0.5 — исправление качества

Аудит пользовательского запуска v0.4 (26 URL, 5 `ok`, 4 `empty_review_required`, 17 `error`, 602 факта) показал проблемы данных и транспорта.

## Что исправлено

1. HTTPS-загрузчик: timeout 35 секунд, до двух повторов временных ошибок, контролируемые HTTPS-редиректы **только в пределах того же домена**, повторная проверка robots.txt для фактического URL. Редирект на другой домен не выполняется автоматически. **SSL-проверку не отключать.**
2. Кодировки: при валидном UTF-8 не доверяем ISO-8859-1 по умолчанию. Для остальных кодировок используется явно объявленная кодировка или определение через BeautifulSoup UnicodeDammit.
3. RuSIEM: родительские группы с подтипами хранятся в `source_family`, а интеграция — как `source_integration` с полным именем `производитель + подтип`. Убирается ложное совпадение `Switch`/`ASA` из разных семейств.
4. Продукты без документированных совпадений больше **не получают фиктивный балл 45**; балл равен `null`, статус `insufficient_evidence`. Это не означает неподдерживаемость SIEM.
5. Опция `--snapshot-dir` сохраняет копии полученных HTML/PDF (локально, вне Git) для ручной проверки; данные содержат разрешённый конечный URL и SHA-256.
6. `--replay-from` позволяет переразобрать сохранённые страницы после исправлений парсеров без повторных сетевых запросов.
7. В манифесте KUMA прописан целевой адрес из замеченного перенаправления; работоспособность URL должна быть проверена в вашем окружении.

## Запуск

```powershell
python -m pip install -e .
python -m unittest discover -s tests -v
python -m siem.etl.all_cli crawl --only p01 p12 --timeout 35 --retries 2 --snapshot-dir results/raw --output results/test_p01_p12.json
python -m siem.etl.all_cli status --etl results/test_p01_p12.json
python -m siem.etl.all_cli crawl --only p01 p12 --replay-from results/test_p01_p12.json --output results/reparsed.json
python -m siem.etl.all_cli crawl --timeout 35 --retries 2 --snapshot-dir results/raw --output results/vendors_v05.json
python -m siem.etl.all_cli assess --etl results/vendors_v05.json --infra data/examples/infra_for_etl.json --output results/fit_v05.json
```

## Что **не исправлено**

- На сайтах нет универсальной структуры HTML/PDF; для каждого семейства документации нужны специализированные адаптеры.
- Наличие URL и HTTP 200 не доказывает, что найдены структурированные характеристики.
- Не вычисляются подтверждённые версии SIEM, все `product_version_verified` пока `null`.
- Текущие `review_candidate` — не технические требования, а короткие текстовые фрагменты.
- Оценка частично документированных продуктов остаётся эвристикой, не использовать для закупки.
- Внешние сайты требуют онлайн-проверки. В среде разработки тесты выполняются на фикстурах, а не с внешним Интернетом.
- Исходные архивы и снимки HTML/PDF не размещать автоматически в публичном Git без проверки условий использования.
