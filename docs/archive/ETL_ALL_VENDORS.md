# ETL для всех 13 SIEM из исходной таблицы (v0.4)

## Принцип

**Один запуск — все продукты.** Манифест `data/etl/vendors.json` содержит 13 идентификаторов `p01`–`p13` из исторической таблицы и 26 URL официальных материалов/документации (для BI.ZONE — публичный материал технологического партнёра Astra). Манифест расширяемый. **26 URL не равны полному охвату документации**, это стартовый реестр точек сбора.

Результат `crawl` — JSON-снимок: время запроса, status каждого URL, контрольная сумма содержимого, извлечённые наблюдения, URL доказательства, версия продукта **если указана**, дата обращения, идентификатор публикации и фрагмент. Весь HTML/PDF в git не сохраняется.

### Запуск (Windows PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m unittest discover -s tests -v
python -m siem.etl.all_cli crawl --dry-run --output results/preview.json
python -m siem.etl.all_cli crawl --output results/vendors_2026-10-27.json
python -m siem.etl.all_cli status --etl results/vendors_2026-10-27.json
python -m siem.etl.all_cli assess --etl results/vendors_2026-10-27.json --infra data/examples/infra_for_etl.json --output results/fit.json
```

Быстрая **офлайн-проверка**, без доступа к сайтам (3 фикстуры, остальные 23 URL отмечены ошибкой `FileNotFoundError` — это ожидаемо):


Для проверки одного вендора:

```powershell

```

Для сравнения демонстрационных условий Kubernetes/серверов (ОБА ПРАВИЛА СИНТЕТИЧЕСКИЕ, не реальные требования продуктов):


**Важно:** `pip install` требует интернета и доступных пакетов; в среде создания архива онлайн-сбор не удалось выполнить из-за отсутствия DNS. Здесь выполнены только офлайн-тесты с тестовыми HTML.

## Семантика полей

- `field=source_integration`, `evidence_status=vendor_catalog` — RuSIEM перечислил источник; версия, коллектор, парсер ещё могут быть неизвестны.
- `field=source_integration`, `evidence_status=vendor_table` — структурированная таблица R-Vision или KUMA, сохранён `source_version`, `collection_method`, `normalizer_id` (когда таблица содержит значения).
- `evidence_status=review_candidate` — фрагмент текстовой документации по оборудованию, требованиям, развертыванию и т.п. **Не использовать как подтверждённую характеристику без проверки**.
- `product_version_hint` — версия, указанная в URL или реестре. Это *не доказательство* применимости факта к этой версии.
- `product_version_verified=null` — автоматическая верификация версии не реализована, данное поле оставлено намеренно пустым.
- `collected_at` — время загрузки; НЕ дата выхода продукта/публикации.
- `source_sha256` — контрольная сумма полученных bytes. Помогает отслеживать изменения.
- `source_document_title` — заголовок страницы/PDF.
- `source_version_verified` — версия **источника событий**, если указана в исходной таблице.

## Схема адаптеров

1. `rusiem`: структурированный перечень семейств/вариантов, без ложных выводов о наличии готового коллектора.
2. `rvision`: официальный справочник с `вендор, продукт, версия, способ подключения, ID правила нормализации`.
3. `kuma`: официальный справочник нормализаторов с названиями систем, типами и описаниями.
4. `generic`: извлечение коротких фрагментов для последующей ручной проверки. Скрипт **не делает выводов о том, что Kubernetes обязателен** лишь по обнаружению слова `Kubernetes`.
5. `pdf`: то же для текстовых PDF без OCR; страницы сохраняются.

Нет данных в открытом реестре, `robots.txt` запрещает страницу, редирект, изменилась HTML-структура, нужен вход, PDF — скан: это разные диагностические статусы, не «SIEM не подходит».

## Алгоритм оценки применимости (исследовательский, настраиваемый)

Только явное совпадение нормализованных названий в официальном перечне считается опубликованной интеграцией. Если источник не упоминается: `not_documented_needs_review`, а не `unsupported`. На каждом источнике можно указать `criticality`, `custom_parser_rub` (собственная гипотеза заказчика). По умолчанию коэффициенты готовности: 0,85 — опубликованная интеграция (не пилот), 0,45 — неподтверждённая; **это модельные параметры, не измеренные вероятности**.

```text
integration_fit = 100 * Σ(criticality_i × readiness_i) / Σcriticality_i
estimated_extra_cost = Σ(estimated_parser_cost_i) + approved_deployment_cost
```

Потребность в Kubernetes/допсервере можно превратить в расчёт затрат **только из отдельно одобренного правила с точной версией продукта и URL**. Подтверждение условий выполнения/версий, исходные сметы и полный TCO — дальнейшая задача. В примере `reviewed_deployment_rules_demo.json` явно проставлены выдуманные версии `DEMO-0` и `example.org`; это проверка формулы, не сведения о Solar/R-Vision.

## Матрица источников и покрытия

| SIEM | Источники, включённые в manifest | Детальный автоматический справочник? |
|---|---|---|
| RuSIEM | официальный перечень парсеров | Да, перечень семейств и вариантов |
| СёрчИнформ SIEM | страница производителя | Пока нет, нужны материалы/каталог контроллеров |
| R-Vision SIEM | таблица нормализаторов + руководство | Да, с версиями и ID правил |
| Alertix | руководство, FAQ, продукт | Пока нет полного каталога: нужна ссылка/формат «Перечень коннекторов» |
| Security Capsule SIEM | описание применения (PDF, 2025) | Нет, кандидатный режим |
| MaxPatrol SIEM | справочник 8.6/8.2 (возможный битый deep-link) | Пока извлечение кандидатов, нужен структурированный каталог |
| САВРУС | официальные страницы | Нет, каталог источников на изображении/недоступен как таблица |
| BI.ZONE SIEM | совместимость с Astra 0.18.0 | Нет, официальный публичный справочник не найден |
| UserGate SIEM | документация 7.x, коллектор/архитектура | Нет, извлечение кандидатов |
| Ankey SIEM NG | официальный портал, релиз 5.2.8 | Нет, но есть PDF руководств, ссылки можно добавить |
| Solar SIEM | официальная архитектура, документация | Нет, извлечение кандидатов |
| KUMA | официальный список нормализаторов 4.0 | Да, названия и типы нормализаторов |
| KOMRAD Enterprise SIEM | официальная документация 4.6.x/4.5 | Нет, извлечение кандидатов |

**Следующий этап:** добавить извлечение ссылок на PDF с ограниченных страниц-индексов (Ankey, Alertix, Solar, MaxPatrol), снапшоты изменений версий, разделение `parser`, `collector`, `normalizer`, `transport` и полноценный человеко-проверяемый слой утверждений. Нельзя обещать полный охват «всех данных» при наличии лишь стартовых 26 ссылок.

## Риски

- Не хранить и не публиковать закрытые КП, реальные сведения об организации и неочищенный Excel.
- Не смешивать `source_version` (версия источника), `product_version` (версия SIEM) и `document_version` (версия руководства).
- Регулярно проверять URL, robots.txt, условия использования документов и ограничения на воспроизведение текста.
- Не принимать маркетинговые значения EPS без профиля тестирования и sizing.
