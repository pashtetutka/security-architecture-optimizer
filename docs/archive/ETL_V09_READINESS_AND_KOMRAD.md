# ETL v0.9 — готовность данных и KOMRAD

## Цель и границы

Две категории: **поддерживаемые источники событий** и **системные требования SIEM**. Стандартизировать формат можно; достоверность и полноту автоматический ETL не гарантирует. Закрытые, недоступные и непубликуемые сведения остаются `null`/`not_extracted`. Нет рейтингов, цен, сертификатов, требований заказчика или заимствований между похожими продуктами.

## Установка на v0.8

1. Сохраните текущие изменения в Git или сделайте резервную копию.
2. Распакуйте `siem-etl-v09-readiness-patch.zip` в корень `security-architecture-optimizer`, сохраняя структуру папок.
3. Выполните:

```powershell
python -m pip install -e .
python -m unittest discover -s tests -v
python -m siem.etl.focused_cli normalize --etl results/vendors_focus_raw.json --output-dir results/focused_v09
python -m siem.etl.focused_cli report --focused-dir results/focused_v09
```

**Не нужен повторный `crawl`**, если сохранены снимки из v0.7/v0.8. Если снимок KOMRAD потерян или не совпадает SHA-256, нормализация оставит запись о проблеме; данные не будут восстановлены догадками.

## Новые и изменённые выходы

- `readiness_report.json` (новый): два независимых статуса по каждой SIEM, количество записей, состояние документов, причины, почему автоматические данные не допущены к расчёту.
- `sizing_profiles.json`: дополнительный адаптер официальной таблицы минимальных характеристик **KOMRAD**, по редакциям Base-SMART / BASE / All-in-One / Enterprise. Физические ядра в `cpu_cores` (не `vcpu`), частота в `cpu_base_frequency_ghz`, единицы дисков сохранены без пересчёта TB→GB.
- `system_requirements.json`: варианты ОС из таблицы KOMRAD как **альтернативные совместимые ОС**, не как список одновременно обязательных ОС; ссылка на сценарий 100 000 EPS — только `capacity_condition`, `sizing_complete=false` (для расчёта отсутствуют полные ресурсы коллекторов).
- `quality_report.json`: сохранён отчёт v0.8.
- `coverage.json` и `sources.json`: прежний формат, нет изменений в импорте поддерживаемых источников.

## Верификация и ограничения

- Извлечённая техническая строка всегда получает `review_status=extracted_unverified`. Для `KOMRAD` поле `document_release` берётся из явно напечатанной в HTML версии документа, но это **не** доказательство установленной версии продукта и не переводит `siem_version` из `null`.
- `calculation_ready=false` для всех автоматически извлечённых данных. Это сознательный жёсткий допуск: требуется отдельный процесс проверки фактов и сопоставления версии заказчиком/экспертом. Отчёт **не является рейтингом SIEM**.
- Названия источников в каталоге SIEM ещё могут содержать дубли, маркетинговые категории и непроверенные интеграции. Не использовать количество строк как метрику продуктового качества.
- Таблица «минимальные требования редакции» **не** означает, что редакция поддерживает 100 000 EPS на этих ресурсах.
- Сведения без локального снимка HTML (`snapshot_path`) или с несовпадающей SHA-256 не извлекаются.
- PDF KUMA 4.0 не парсится этим патчем. Также не заявляется полнота по остальным 13 продуктам.
- Интеграции Ankey SIEM NG не наследуются от MaxPatrol без отдельного подтверждения.

## Официальный источник KOMRAD

`https://docs.etecs.ru/komrad/docs/next/install/prerequisites/` — документация ветки **4.6.X** (страница содержит таблицу редакций и описывает отдельную конфигурацию на 100 000 EPS). В патче извлекаются исключительно поля, подтверждённые этим документом. Возможные изменения страницы при новом crawl должны заново пройти проверку.

## Критерии приемки v0.9

1. Никаких новых полей о сертификатах, ценах или функциях SIEM.
2. `python -m unittest discover -s tests -v` — все 75 тестов успешно проходят на подготовленных данных.
3. `normalize` выполняется на ранее сохранённом `results/vendors_focus_raw.json` и записывает `readiness_report.json`.
4. Продукты с недостатком сведений честно остаются `not_extracted`, а не `unsupported`.
5. До просмотра JSON и исходной документации нельзя использовать результаты в автоматическом ранжировании и расчётах.

Если у KOMRAD остается 0 профилей, нужны сам HTML-снимок из `results/raw`, объект `source_results` этой страницы и `unparsed_system_documents.json`: без этого нельзя считать адаптер подтверждённым на реальном сайте.
