**Текущий фокус: только SIEM, все 13 продуктов исходной таблицы.**

### Новый ETL для всех SIEM (v0.4)

- [Методика, перечень источников, команды запуска и ограничения](docs/ETL_ALL_VENDORS.md)
- Реестр 13 продуктов и 26 URL: `data/etl/vendors.json`
- `python -m siem.etl.all_cli crawl --output results/vendors.json` — по команде опрашивает все источники, пишет JSON с каждой ссылкой, версией и статусом.
- `python -m siem.etl.all_cli assess --etl results/vendors.json --infra data/examples/infra_for_etl.json --output results/fit.json` — условная градиентная оценка применимости и допзатрат по инфраструктуре.
- Проверка на неполных/ошибочных данных, официальных таблицах KUMA и R-Vision (офлайн HTML) и архитектурных условиях (синтетические правила).

## Сделано
- Перенесены из листа `РасчетSIEM` **13 альтернатив, 15 критериев, исходные значения, нормализованные оценки, приоритеты и веса**. Названия и исторические значения сохранены без замены синтетическими.
- Прототип опросного листа (веб-приложение Streamlit): бюджет, КИИ, сертификация, типы и количества источников, оценка EPS, пиковая нагрузка и запас.
- Два метода выбора: weighted sum и TOPSIS; устойчивость первого места к случайным изменениям весов.
- Предварительный бюджетный фильтр; диагностические предупреждения, графики и экспорт JSON.
- Юнит-тесты и демонстрационный профиль инфраструктуры.

## Методологические оговорки
- Это **реплика исходной количественной модели плюс экспериментальные методы**, а не готовая закупочная экспертиза.
- Исторические критерии и цены не верифицированы на текущую дату; `Первоначальное КП` не равно TCO.
- `EPS-тариф` — тарифное число из таблицы, **не подтверждённая техническая мощность**. Его недостаток пока даёт предупреждение, а не автоматический отказ.
- `Источников событий` в количественном листе — количество готовых источников/интеграций в оценке автора, а не список поддерживаемых конкретных коннекторов. Поэтому проверка точного покрытия пока не автоматизирована.
- Сертификация ФСТЭК и КИИ в текущей версии **не являются подтверждёнными фильтрами**: невозможно достоверно интерпретировать статус на основании числового листа без проверки качественных сведений, версии, срока и области применения.
- Коэффициенты EPS в демонстрационных сценариях — **допущения пользователя**, их надо уточнять пилотом/статистикой. Не считать нормативом.
- Правила нормализации из сохранённой колонки не переписываются; библиотечная функция min/max нужна для экспериментов.
- Для полноценного выбора необходимы подтверждаемые источники, стоимость коннекторов, внедрения и эксплуатации, ресурсы и архитектурные ограничения.
- На листе `АнализSIEM` качественные параметры присутствуют, но его продукты не полностью совпадают с количественным листом. Нужны ручная сверка и схема маппинга. Он **не участвует автоматически в фильтрации**.

## Следующая итерация
1. Проверить формулы Excel, способы нормализации и весовую модель (проверить расхождения по всем продуктам).
2. Сопоставить 272 строки качественного анализа с количественной моделью (версия/продукт/достоверность).
3. Каталог коннекторов: `SIEM → тип источника → способ сбора → поддерживается из коробки / платный коннектор / кастомная разработка`.
4. TCO: лицензия, hardware, внедрение, сопровождение, коннекторы, обновление/расширение.
5. Результативность: проверить рекомендации на нескольких реалистичных инфраструктурных профилях, оценить расхождение TOPSIS/WSM, провести анализ чувствительности и устойчивости.

## Подсистема ETL (v0.3, первый прототип)

- Адаптер для **официального списка RuSIEM**: извлекает семейство продукта и варианты,
  URL и дату, контрольную сумму содержимого. Онлайн-проверка недоступна из среды сборки,
  тесты выполнялись на локальной HTML-фикстуре.
- Отдельный алгоритм сопоставления с перечнем источников организации: точный вариант,
  семейство, нет сведений. Нет сведений **не равно** несовместимо.
- Локальный PDF-extractor для **кандидатов** из документации PT с сохранением страницы
  и URL; человеческая проверка обязательна.
- Периодический workflow GitHub Actions, создающий артефакт для ручной проверки,
  **без автоматического коммита данных**.
