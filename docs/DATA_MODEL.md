# Модель данных MVP

## Организация
- `min_eps`: минимальная подтверждённая производительность, EPS.
- `require_on_premise`: обязательность локального развёртывания.
- `required_integrations`: список обязательных интеграций.
- `weights`: веса критериев многокритериального выбора.

## Каталог продукта
- `id`: идентификатор без привязки к вендору.
- `eps`: подтверждаемая производительность в условном сценарии.
- `on_premise`: возможность локального развёртывания.
- `integrations`: подтверждённые интеграции.
- `scores`: оценки 0–100 для критериев.

## Эволюция модели
Для реальных данных понадобится отдельная таблица «утверждения о продукте»:
`product_id`, `attribute`, `value`, `unit`, `source_url`,
`source_type`, `observed_at`, `product_version`, `confidence`,
`review_status`, `reviewer`. LLM-предложения не становятся проверенными
утверждениями до ревью.

Требование EPS не должно применяться как универсальная цифра без фиксации
профиля нагрузки, пиковых значений и параметров развёртывания.
