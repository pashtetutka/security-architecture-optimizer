# Исследовательский прототип выбора SIEM

В `src/siem/core.py` находятся расчёт EPS, предварительный бюджетный фильтр,
взвешенная сумма, TOPSIS и анализ чувствительности. CLI в `src/siem/cli.py`,
интерфейс Streamlit в `app.py`. Данные исходного авторского сравнения сохранены
в `data/reference_metrics.json`; демонстрационный профиль — в `data/demo_infra.json`.

По умолчанию интерфейс открывает раздел «Организации»: пять синтетических
опросных листов малых и средних организаций (16–18 строк, тип,
производитель/модель, версия, количество) из `data/scenarios/` и предварительный отчёт по 13 SIEM на
основании сохранённых снимков ETL. Старый числовой расчёт доступен отдельным
разделом «Исторический расчёт». Предварительный отчёт не присваивает баллы
качества и не объявляет отсутствующую запись доказательством неподдержки.
Шестой готовый лист — организация пользователя с 23 строками — лежит в том же
`data/scenarios/`, загружается тем же валидатором и обрабатывается тем же
сопоставлением. Входные совпадения с отдельными SIEM в лист не записываются.
Если одна строка содержит несколько продуктов, поле `products` перечисляет их
по отдельности; `products_match` указывает, нужны все компоненты или достаточно
любого. `product_family` хранит только подсказку для ручной проверки: запись о
семействе не считается подтверждённой интеграцией конкретного продукта.
Сопоставление использует единые идентификаторы источников из ETL для всех SIEM.
Показатель «засчитано строк» считает прямые совпадения продукта любой указанной
версии. Расхождение версий остаётся в `version_candidate`, а строка отчёта
сохраняет `counted_for_coverage`, `version_review_required`, `requested_version`,
`version_scope` и опубликованную `evidence[].source_version`. Поле
`required_published` сохраняет прежний строгий подсчёт; `required_counted`
содержит новый подсчёт для покрытия. Эти значения не подтверждают совместимость
конкретной модели и версии; будущая многокритериальная оценка может учитывать
отдельно наличие продукта и риск версии. Отсутствие строки в текущей выгрузке
не доказывает, что продукт SIEM её не поддерживает.
По принятой политике частично поддерживаемый продукт также засчитывается,
но сохраняет `partial_support=true`, исходный `support_scope` и ограничения.
Отсутствующий обязательный компонент составной строки не компенсируется
частичной поддержкой другого компонента. Аналитический отчёт читает также
сохранённые официальные импортированные документы и показывает
`evidence[].acquisition_method`; `--automatic-only` в CLI по-прежнему исключает их.
Если в документе продукт и числовая версия разделены по колонкам, сопоставление
понимает запись вида «Континент-4» как продукт «Континент» версии 4. Такое
совпадение требует точного совпадения базового названия продукта; при другой
версии строка засчитывается с пометкой `version_review_required`. Тип источника
и поток журнала в опроснике хранятся отдельно от имени продукта. Если с одного
устройства заявлено несколько потоков, `collection_scope_review_required`
напоминает проверить каждый поток: публикация продукта сама по себе не
доказывает наличие отдельного парсера для каждой функции устройства.
ETL дополнительно публикует `source_match_keys`: явные названия продукта,
название без документированной числовой версии и перечисленные в одной ячейке
конкретные продукты того же производителя. Исходная формулировка и версия
остаются в отдельных полях. Для составного требования отчёт содержит
`component_assessments`, поэтому подтверждение одного продукта из двух не
превращается в полное покрытие строки. Алиас ROSA Virtualization / РОСА
Виртуализация действует для всех SIEM.

В пользовательском опросном листе Postgres Pro Enterprise 16 сохранён как
редакция СУБД версии 16. Исходная подпись Kaspersky EDR Optimum заменена по
уточнению владельца на Kaspersky Security Center без выдуманной версии.
«1С:Предприятие 8.3 КОРП» приведено к платформе «1С:Предприятие» версии 8.3;
конфигурация ЭДО неизвестна и отмечена для проверки области собираемых событий.
Рабочие станции Windows 7/10 могут сопоставляться как с явной записью об ОС,
так и с журналом Windows Security. Диапазон лет в документации нельзя напрямую
сравнивать с номерами клиентских ОС; в этом случае источник засчитывается, но
`version_review_required` остаётся истинным.
Построчная сверка MaxPatrol с тем же опросным листом и сохранённой таблицей 8.6
находится в [`maxpatrol_questionnaire_audit.md`](maxpatrol_questionnaire_audit.md).
EPS, численность и площадки, которых нет в исходном снимке, остаются неизвестными;
инженерная модель EPS показывается отдельно от измеренных значений.

```powershell
python -m siem.cli --method topsis --sensitivity 200
python -m pip install streamlit pandas
streamlit run app.py
```

Исторические оценки, цены и признаки сертификации не подтверждены на текущую дату.
Показатель EPS в исходной таблице нельзя считать технической мощностью без сценария
нагрузки. Выгрузка ETL хранит извлечённые факты отдельно и автоматически не меняет
исходные оценки. Расчёт служит исследовательским примером, а не готовой закупочной
экспертизой.

Проверки расчёта находятся в `tests/test_core.py`. Команды выше генерируют
результаты. Примеры входов ETL находятся в `data/examples/`.
