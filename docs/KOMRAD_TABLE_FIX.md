# Исправление таблицы KOMRAD, 2026-10-28

Источник: сохранённый `results/raw/p13/hardware_requirements_49bf901b512592.html`,
документация 4.6.X, URL https://docs.etecs.ru/komrad/docs/next/install/prerequisites/.
SHA-256: `49bf901b51259254bf10d15567886cd370de30f3475cf7909de6df94781d1f4b`.
Хеш совпадает с записью `hardware_requirements` в `results/vendors_focus_raw.json`.
В `results/vendors_novpn.json` этой записи нет, поэтому для повторной нормализации
использован focused raw.

Причина: исходный HTML опускает закрывающие теги th, td, tr. BeautifulSoup
с html.parser вкладывает соседние ячейки и строки друг в друга. Обход только
непосредственных дочерних ячеек терял заголовки редакций; таблица ОС также
не распознавалась. Поиск EPS по тексту не зависит от структуры таблицы.
Старые синтетические тесты содержали явные закрывающие теги.

В `src/siem/etl/vendors/komrad.py` таблицы KOMRAD читаются в порядке исходных элементов;
начала tr/td/th задают границы строк и ячеек. Другие адаптеры не изменены.
Добавлено поле `applicability` с редакцией, уровнем minimum, версией документа
и булевым eps_sizing=false. Редакция, ядра CPU, частота GHz, RAM GB и ёмкость
диска с единицей GB/TB остаются отдельными типизированными полями.

| Редакция | Ядра | GHz | RAM GB | Диск |
|---|---:|---:|---:|---|
| Base-SMART | 2 | 2 | 8 | 100 GB |
| BASE | 2 | 2 | 8 | 100 GB |
| All-in-One | 2 | 2 | 16 | 1 TB |
| Enterprise | 4 | 2 | 32 | 10 TB |

Копия исходного файла без преобразований добавлена в
`tests/fixtures/komrad_prerequisites_4_6.html`. Тест проверяет SHA-256,
все четыре профиля, ОС, отдельное условие EPS и путь нормализации с проверкой
хеша. Дополнительные проверки покрывают inline-разметку, неразрывные пробелы
и отказ от таблицы с объединёнными ячейками.

Проверки:

```powershell
python -m unittest discover -s tests -v
python -m siem.etl normalize --etl results/vendors_focus_raw.json --output-dir results/focused_v09
```

До исправления: 75 тестов, 74 успешных, один skip. После: 78 тестов,
77 успешных, один skip (PyMuPDF отсутствует).
Контрольная нормализация до изменения сохранена в `results/komrad_before`.
KOMRAD: профили 0 → 4, требования 1 → 7 (шесть вариантов ОС и условие EPS).
Всего: профили 11 → 15, требования 8 → 14. Сравнение JSON подтвердило
полное равенство sources.json и равенство всех записей других продуктов
в sizing_profiles.json и system_requirements.json.

Ограничения: вложенные таблицы и rowspan/colspan не поддерживаются этим
адаптером. Минимальные ресурсы редакций не задают производительность EPS;
сценарий 100 000 EPS по-прежнему неполон для расчёта ресурсов коллекторов.
GB/TB не пересчитываются друг в друга. Данные остаются extracted_unverified,
версия установленного продукта неизвестна; calculation_ready=false.
Коммиты не создавались.
