# Ручная сверка пяти SIEM с опросным листом инженерной организации

Дата: 14.11.2026. Проверено 23 строки листа `data/scenarios/s06_engineering.json`
по каждой из пяти SIEM. Таблица составлена чтением документов и названий
источников; результаты алгоритма сопоставления не использованы как доказательство.
Поиск по тексту и извлечение текста HTML/PDF применялись для навигации.

Обозначения: **П** — конкретный продукт или требуемый журнал явно назван;
**М** — описан общий маршрут сбора журналов ОС, но конкретная служба не названа;
**К** — кандидат, недостаточно для зачёта конкретного продукта;
**Н** — по доступным документам не подтверждено. Ни один из этих статусов не
означает, что техническая интеграция невозможна. Версии, редакции и отдельные
потоки одного устройства требуют дополнительных проверок, указанных ниже.

## Документы и ограничения

**B0 — BI.ZONE SIEM.** В текущем реестре есть только страница совместимости с
ОС Astra, загрузка которой запрещена `robots.txt`. Каталог продуктов-источников
в доступном наборе отсутствует. Поиск по официальным доменам BI.ZONE не дал
доступного перечня коннекторов именно BI.ZONE SIEM; документация EDR и
общеобразовательные статьи о SIEM таким перечнем не являются. Все 23 строки —
не подтверждены, а не «не поддерживаются».

**U1 — UserGate SIEM.**
[Архитектура](https://docs.usergate.com/arhitektura-siem_1900.html), снимок
`data/etl/repro/raw/p09/architecture_7b84f0e3e02f5c.html`;
[сборщик логов](https://docs.usergate.com/obshie-svedeniya_1928.html), снимок
`data/etl/repro/raw/p09/collection_2cfd285d1b8aaf.html`.
Архитектура прямо описывает сенсор WMI для компьютеров Windows и параметры
Windows event-log. Общий приём Syslog/SNMP не доказывает наличие парсера
конкретного D-Link, Континент, Kaspersky и других продуктов.

**A1 — Ankey SIEM NG.**
[Страница продукта](https://www.infogaz-is.ru/produkty/upravlenie-ib/ankey-siem-ng),
снимок `data/etl/repro/raw/p10/product_docs_9685e1e1afbed8.html`;
[релиз 5.2.8](https://www.infogaz-is.ru/o-kompanii/novosti/2442-ankey-siem-next-generation-ankey-siem-ng-5-2-8),
снимок `data/etl/repro/raw/p10/release_aab1459a2f62a1.html`.
В релизе заявлено более 200 типов источников, но упомянутые таблицы 3.1/3.2
в сохранённом HTML отсутствуют. На странице продукта найдены ссылки
`/files/products/ankey-siem-ng/D-link.pdf`,
`/files/products/ankey-siem-ng/GIS-Ankey-SIEM-NG-Backup.pdf`,
`/files/products/ankey-siem-ng/avpo.pdf`. PDF не удалось прочитать: проверка
TLS на `www.infogaz-is.ru` и `infogaz-is.ru` завершается hostname mismatch.
Проверка TLS не отключалась. Журнал попыток находится в
`results/history/manual_remaining_20261114_02/manifest.json` и `..._03/manifest.json`.
Название ссылки D-Link является кандидатом, но не доказывает модель DFL-1660;
название Backup не устанавливает конкретный продукт резервного копирования.
Описание пакета обнаружения атак Windows не приравнивается к перечню
поддерживаемых источников событий.

**S1 — Solar SIEM.** White Paper v2025.3, печатная страница 7,
`data/etl/repro/raw/p11/source_whitepaper_9e4d4648aff7aa.pdf`;
[официальный PDF](https://rt-solar.ru/upload/docs/solar-siem/Solar%20SIEM_v2025.3_White%20Paper_Website.pdf).
Явно перечислены Windows Event Log, Microsoft DHCP Server, Microsoft Windows
DNS Server и PostgreSQL. Общие журналы СЗИ/CEF и произвольные файлы не дают
права объявить поддержанными все продукты опросника. PDF прочитан `pypdf`;
PyMuPDF в окружении отсутствует. Для текстового перечня источников этого
достаточно, таблицы с координатами не проверялись.

**K1 — KOMRAD Enterprise SIEM.**
[Каталог источников](https://docs.etecs.ru/komrad/docs/next/collect/sources/),
снимок `data/etl/repro/raw/p13/sources_catalog_87e67b58339816.html`.
Снимок относится к будущей документации 4.6.X (`next`), а не к автоматически
проверенной выпущенной версии продукта. 44 карточки источников прочитаны
по заголовкам, описания карточек не являются частью названия продукта.

**K2 — дополнительные страницы KOMRAD.** Оригинальные HTML получены через
`PublicFetcher` с проверкой `robots.txt` и TLS, сохранены с URL, временем и
SHA-256 в `results/history/manual_remaining_20261114_02/manifest.json`:

- [Кибер Резервное копирование](https://docs.etecs.ru/komrad/docs/next/collect/sources/cyberbackup/):
  сбор событий выполнения плана резервного копирования из Windows Application
  через WMI; не все события панели управления продуктом.
- [StaffCop Enterprise](https://docs.etecs.ru/komrad/docs/next/collect/sources/staffcop/):
  инциденты через Syslog/CEF, настройка соответствующей политики и коллектора.
- [Winlogbeat](https://docs.etecs.ru/komrad/docs/next/collect/sources/winlogbeat/):
  Windows Application, System, Security, PowerShell, ForwardedEvents через
  настроенный HTTP-коллектор. Само наличие карточки Winlogbeat без чтения
  страницы нельзя использовать как алиас любой ОС.

## Расхождения с автоматическим результатом и изменения

1. **KOMRAD — ошибка структуры карточек.** Парсер склеивал заголовок и
   описание ссылки: например, название KSC включало текст инструкции.
   Из-за лимита длины три карточки пропадали совсем. Исправлен выбор
   `h2`/`title`; теперь извлекаются 44 карточки вместо 41. Регрессионный
   тест использует реальный сохранённый HTML, `tests.test_komrad` — 11 OK.
2. **KOMRAD — общие алиасы.** Для сопоставления нужны пары названий
   Dallas Lock / Dallas Lock 8.0-К,
   Exchange Server / Microsoft Exchange Server 2010 и уточнённая связь
   Кибер Бэкап / Кибер Резервное копирование. Ограничения дочерней страницы
   Кибер-продукта должны сохраняться вместе с совпадением. StaffCop Enterprise
   остаётся кандидатом редакции; автоматический алиас всего семейства не введён.
3. **UserGate и Solar — пропуск Windows.** Названия `Windows computer` и
   `Windows event logs` описывают тот же требуемый сбор журналов рабочих
   станций, но точное сравнение с «Windows 7, Windows 10» его теряло.
   Сопоставление должно сохранять неизвестную область версий.
4. **KOMRAD — новый источник документа.** Winlogbeat описывает сбор Windows
   Security/System, но его страница ранее не входила в сохранённый реестр.
   Оригинал теперь сохранён; для автоматического зачёта нужен отдельный
   зарегистрированный документ/адаптер, а не алиас «Winlogbeat = Windows».
5. **BI.ZONE и Ankey.** Нулевой автоматический результат нельзя читать как
   отсутствие поддержки. Для BI.ZONE нет доступного каталога; для Ankey
   обнаружены полезные официальные PDF, но их содержимое пока не проверено.

Эта ручная таблица предназначена для аудита и не подмешивается в ETL как
подтверждённый каталог. Новые автоматически извлекаемые факты должны ссылаться
на сохранённые первоисточники с проверенными хешами.
