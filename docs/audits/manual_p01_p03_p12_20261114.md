выведены из результата `assess_organization`. Поиск и извлечение текста таблиц

Обозначения: **да** — назван продукт/журнал, версия может требовать проверки;
**кандидат** — названа только платформа, родственный продукт или редакция;
**нет записи** — источник не найден в проверенном документе, без вывода
`unsupported`. Зачёт продукта не доказывает сбор каждого журнала устройства.

## Найденные расхождения и общие исправления

1. KUMA: `Microsoft DHCP` → `Microsoft DHCP Server`, `Microsoft DNS` →
   `Microsoft DNS Server` — безопасные алиасы, подтверждённые описанием строки.
2. KUMA: `Конфидент - Dallas Lock` → `Dallas Lock` — опубликованный
   производитель в составе названия, не другой продукт. Редакцию К сохранить
   как неподтверждённую.
3. KUMA: `Staffcop Enterprise` нельзя без проверки редакции слить с общим
   `Staffcop`; нужен кандидат, а не отсутствие записи.
4. KUMA: `1C EventJournal` / `1C TechJournal` должны сопоставляться с
   платформенным журналом 1С, а не исчезать из анализа. Для строки 23
   засчитывается платформа с проверкой области ЭДО; строка 16 остаётся
   кандидатом, поскольку конфигурации отдельно не названы.
5. RuSIEM: Windows Server 2019 должен сопоставляться с опубликованными версиями
   Windows Server по принятой пользователем политике любой версии. Версия и
   функциональная область AD требуют отдельных пометок.
6. KUMA: частичная обработка событий ESXi, Windows и DNS опубликована в
   описаниях нормализаторов; сохранять ограничение вместе с зачётом источника.
