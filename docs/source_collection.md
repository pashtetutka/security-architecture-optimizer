# Доступность каталогов источников событий

Для воспроизводимой проверки без сети используйте набор
`data/etl/repro/vendors.json` и исходные снимки `data/etl/repro/raw/`.
Команда из корня репозитория: `python -m siem.etl check --etl data/etl/repro/vendors.json`.
Она не меняет исходные документы и ожидаемо выдаёт 1630 записей источников,
16 аппаратных профилей и 26 требований. `results/` ниже — локальные
исследовательские артефакты; они не входят в Git.

## Обновление 31 октября 2026 года

**TLS MaxPatrol исправлен для отдельного хоста ETL. Каталог: 1402 → 1630 записей.**

Windows показала точную причину: цепочка `*.ptsecurity.com → Russian Trusted Sub CA → Russian Trusted Root CA`, статус `UntrustedRoot`. Корневой сертификат получен с официального ресурса Госуслуг по HTTPS с обычной проверкой доверия: `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`. SHA-256 полученного PEM: `936a43fea6e8e525bcc0f81acd9c3d21b4fc4b9b68acea7906d698005afc6504`. Системное хранилище Windows и certifi не изменялись.

Загрузчик теперь принимает явное `--host-ca HOST=PEM`: CA используется только для точного хоста, включая robots.txt и разрешённые перенаправления в пределах этого хоста. Для остальных доменов доверие остаётся прежним. Ошибочные сертификаты и запреты robots.txt не обходятся.

После восстановления TLS выяснилось, что адреса страниц возвращают пустую оболочку SPA. Сохранённый JavaScript самого портала указал публичный API: `https://help.ptsecurity.com/api/v2/documents/document/ru-RU/siem/8.6/help/1083652747`. Получен исходный JSON с HTML-таблицей, извлечены **228 строк** с версиями источников и стандартными профилями сбора. JSON сохраняется без изменений, его SHA-256 используется в evidence. Производитель извлекается только из явной записи. Профиль сбора не выдаётся за ID нормализатора. Версия 8.6 остаётся версией документации, а не автоматически проверенной версией продукта.

MaxPatrol теперь содержит **407 записей: 228 из таблицы поддерживаемых источников + прежние 179 частичной поддержки**. Это не утверждение о 407 уникальных продуктах: области поддержки и версии сохраняются раздельно.

Особенность портала: `/robots.txt` также возвращает HTTP 200 с HTML-оболочкой; стандартный `RobotFileParser` не находит в ней запрещающих директив. Этот ответ сохранён отдельно в `results/tls_retry_20261031_a/robots.txt`; это не полноценный текстовый robots.txt.

Повтор 31.10: **СёрчИнформ, Ankey и UserGate** снова получили тайм-аут проверки robots.txt (25 секунд). **САВРУС** — ранее подтверждённый запрет robots.txt для руководств; повторно запрещённые документы не скачивались. **BI.ZONE** — отдельный публичный каталог SIEM по-прежнему не найден, нового поиска в этом проходе не было. **Security Capsule** — сохраняется ограничение размера презентации; в этом проходе повторной загрузки не было. У RuSIEM, R-Vision, Alertix, KUMA, KOMRAD и Solar доступны прежние локальные наборы; это не подтверждение полноты или текущей доступности всех сайтов.

Артефакты: `results/tls_retry_20261031_a/` — диагностика Windows, CA и манифест его получения, повторные попытки, `maxpatrol_crawl.json` и исходные снимки, входы до/после и `comparison.json`. Сравнение подтвердило неизменность остальных SIEM, прежней частичной поддержки MaxPatrol и всех системных требований.

Уборка тестов: удалены пять дублирующих/слабых тестов (наличие файлов, отдельный дефис вместо версии, синтетический минимальный workflow, повтор четырёх профилей KOMRAD, отдельный тест значка в именах). Полезные утверждения объединены с тестами на реальных снимках; отдельный `test_komrad_source_names.py` удалён. Удалены два временных PS1-скрипта неудачной диагностики; снимки, манифесты и старые результаты сохранены. Добавлены пять проверок ограниченного TLS-доверия и три проверки нового API-адаптера.

Итоговая проверка: `results/history/check_20261031_131747_aa1d4a94/`, 106 тестов — 105 успешно, один пропущен (не установлен PyMuPDF). Каталог содержит 1630 записей, 16 аппаратных профилей и 26 требований. Машиночитаемая сводка: `results/tls_retry_20261031_a/source_availability.json`.

## Воспроизводимость и проверки

Все попытки, полные ошибки, URL, время получения и SHA-256 успешных загрузок находятся в `results/source_research_20261030_a/batch*_manifest.json`; исходные HTML/PDF — в соседнем `raw/`. Наличие скачанного документа само по себе не означает, что он нормализован. Даты относятся к получению, не к подтверждению версии продукта.

Машиночитаемая сводка по 13 SIEM: `results/source_research_20261030_a/source_availability.json`. Презентация Security Capsule по ссылке с официальной страницы оказалась больше лимита: сначала 8 МБ, затем 32 МБ при отдельной исследовательской попытке. Это ограничение загрузчика, а не запрет доступа; неполные ответы не сохранены как исходные документы. В последней попытке поле `max_bytes=32000000` задаёт фактический предел, несмотря на фиксированный текст ошибки стандартного загрузчика «8 МБ».

Предыдущий вход сохранён в `results/source_research_20261030_a/vendors_focus_raw_before.json`, новый — в `vendors_focus_raw_after.json` и текущем `results/vendors_focus_raw.json`. Исходные снимки не изменялись. Новые официальные документы также включены в реестр загрузчика.

Регрессионные тесты проверяют реальные неизменённые HTML/PDF по SHA-256, имена источников, страницу PDF, неизвестные версии, отсутствие двойного счёта Windows/Linux и диагностику ошибочного PDF/хеша. Проверка `python -m siem.etl check`: 103 теста, 102 успешно, 1 пропущен из-за отсутствия необязательного PyMuPDF. Новое извлечение PDF через pypdf проверено; пропуск относится к отдельному старому тесту.

Результат: `results/history/check_20261030_172120_1973525e/`. Сравнение полных записей в `comparison.json` подтверждает неизменность остальных 11 SIEM, 16 аппаратных профилей и 26 требований. Все записи остаются `extracted_unverified`; готовность к расчёту автоматически не присваивается.

**Установленный предел:** сейчас можно доказать запрет автоматического скачивания конкретных руководств САВРУС. Для остальных пробелов зафиксированы технические препятствия либо отсутствие найденного публичного каталога; утверждать «данные этой SIEM собрать невозможно» оснований нет.
