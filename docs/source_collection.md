# Происхождение и ограничения данных

Воспроизводимый вход: `data/etl/repro/vendors.json` и 37 неизменённых оригиналов
в `data/etl/repro/raw/`. У каждого документа зафиксированы URL, время получения,
SHA-256, способ получения и статус. Этот набор подтверждает результаты на дату
сохранения документов; доступность сайтов сегодня проверяется новым сбором.

```powershell
python -m siem.etl check --etl data/etl/repro/vendors.json --automatic-only
```

Результат: 1451 запись источников, 25 профилей ресурсов и 67 требований.
`--automatic-only` допускает только документы с `acquisition_method=automatic_https`;
неизвестное происхождение и ручной импорт исключаются.

Без этого флага исторический набор включает 179 записей частичной поддержки
MaxPatrol из вручную сохранённой страницы (всего 1630). Автоматически разобранный
HTML ручного импорта не считается автоматически загруженным документом.
Его строки имеют `support_scope=partial`; оригинал сохранён для аудита.
В текущем реестре эта страница отключена; автоматический каталог MaxPatrol
использует публичный JSON API и содержит 228 записей.

Для MaxPatrol ранее требовался отдельный доверенный CA. Параметр `--host-ca`
действует только для указанного хоста и сохраняет проверку TLS. HTML-оболочка
в ответ на `/robots.txt` теперь даёт `robots_unavailable`, поэтому новая загрузка
может остановиться раньше обращения к API. Сохранённый ответ API остаётся
воспроизводимым доказательством его содержимого, но не разрешения на новый сбор.

Непрочитанных доступных снимков и неразобранных системных документов в контрольном
наборе нет. Средний профиль Ankey содержит противоречие первоисточника: заявлено
два сервера, перечислены три роли. Оба значения сохранены с диагностикой.
Некоторые документы отсутствуют, закрыты, запрещены robots.txt или не содержат
нужных параметров. Это не доказывает, что интеграция не поддерживается или что
получить параметры невозможно иным официальным способом.

По каждому продукту см. [vendor_audit.md](vendor_audit.md). Подробная диагностика
нового запуска находится в `readiness_report.json`, `quality_report.json` и
`schema_validation.json`; HTML-обзор — `results/etl_audit/report.html`.
Автоматическое извлечение не устанавливает `verified` и `calculation_ready=true`.
